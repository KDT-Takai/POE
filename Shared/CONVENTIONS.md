# コーディング規約（命名以外）

命名規則は `NAMING.md` を参照。ここでは命名以外のルールをまとめる。

## コメント

- **コメントは極力書かない。** コードを見れば分かることをコメントで繰り返さない。
- AI（Claude Code等）はコードを読めば理解できるので、説明用のコメントは不要。
  コメントを書くほど、後から読むAI・人間双方のコンテキスト消費が増える。
- 書いてよいのは「なぜそうしたか」が非自明な場合のみ（隠れた制約、既知のバグの回避、
  一見不可解に見える実装の理由など）。「何をしているか」の説明は書かない。

## 文字エンコーディング

- 日本語コンテンツを含む新規ファイルはUTF-8 BOM付きで保存する（文字化け対策）。
- 新規システム（Item/Currency/UI等）のテキストは原則英語表記とし、文字化けリスクを避ける。
- `CampaignManager.cpp` は例外的に `/utf-8` per-fileコンパイルオプションを指定している。

## ECS設計

- コンポーネントはデータのみ（メソッドを持たせても`PowerScore()`のような単純な派生値計算まで）。
  ゲームロジックはシステム側（`Systems/`）に置く。
- システムは基本的にヘッダオンリーのクラスとし、`Update(Registry&, float dt)` / `Render(Registry&, sf::RenderTarget&)`
  という命名のメソッドで呼び出す（既存システムの慣習に合わせる）。

## ビルド関連

- 新規ヘッダファイルを追加したら `Game-SFML.vcxproj` の `ClInclude` にも追記する。
- NuGetパッケージ（`Microsoft.Windows.CppWinRT`）は `packages.config` 方式。復元は
  `nuget.exe restore Game-SFML.sln`（MSBuildの`/t:Restore`だけでは復元されない）。
